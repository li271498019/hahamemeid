# 10 上线顺序、验收门、故障

不承诺在北京时间 2026-11-24 08:00 前完成。那个时刻就是 `START_TS`。验收门没过，`redeemOpen` 保持关闭。这是阻塞：日期不顺延，已经开始的窗口不补开、不改成从验收通过的那天重新算 15 天。不能跳过验收去赶上线。合成一个合约只是建议；拆成两个合约不改变这个时间。

## 顺序

1. D 在本目录规格上实现合约与 `09` 的测试。`forge test` 全绿，包括原有测试。
2. 字节码体积记录进 PR。超过 24576 就按 `02` 拆分，而不是删检查。
3. anvil 上跑面板 `07` 的 1–8 步。确认深度用 15，预算用已批准数字。这些交易留在本地链，不复制到主网。
4. 提交人A 的复算脚本与 D 的 Merkle 向量对上同一个 root。
5. 日奖公钥尚未公布时，主网第 7 步保持空白。这不是产品规则未定，只是地址还没生成。
6. 管理员在主网签 `07` 的已填步骤。第 9 步先不打开开关。验收没过就一直关着，日期不顺延。
7. 主网只读验收：地址、`earn` 配置读回、`isSpender`、预算、actionId 没有覆盖旧的三个 earner。内置签到等参数与部署时相同（签到 30、铸造 10、关注 30、点赞 10、转发 10、评论 10）。
8. 用一个不会成功的签名做 `eth_call`，确认模块会拒绝错误 root。不要发真实兑换。
9. 第一天的 manifest 公开，复算 root 一致，然后管理员才 `setDayRoot` 并打开 `redeemOpen`。验证开关可以同一天打开，若签名人和任务包还没就绪就保持 `rewardsOpen = false`。

每一步的交易哈希记在部署笔记里。笔记不进含私钥的环境文件。

## 验收门

缺一不可：

- `09` 全部必测通过，fork 夹具至少覆盖一个真实历史块的余额。
- 面板在日奖公钥为空时不能发出 `setValidator`。预算和三笔 `setEarner` 使用 `02` 的已批准数字，不得改回空框或改回 100 万。
- 20 笔发放在 anvil 上是 20 次签名，不是一次。
- 索引器能从 `Redeemed` 重建订单，重组测试删块后不出现双扣。
- 网站申请按钮在复算 root 不一致时不出现。这一项是提交人A 的门，不是 D 单独宣布上线。

## 风险与恢复

| 情况 | 链上事实 | 允许的动作 | 不允许 |
| --- | --- | --- | --- |
| 用户交易 revert | 无订单、未扣分 | 用户重试 | 后台补扣 |
| 已 `Pending`，管理员还没铸 | 200 已扣，名字已锁 | 超时后对同一接收人补 `adminMint` | 退款、换名、再扣、占新一天 |
| 模拟 `NameTaken` | 名字已在 Registrar | 停在该行，交给 L | 脚本自动换一个名字 |
| 错误 root 且已有人申请 | 订单按错误资格扣了分 | 关掉 `redeemOpen`，公开两边 root | 换 root、静默退款 |
| 快照块被重组且尚无订单 | 无扣分 | 按 `03` 在新主链上重新锁定日界前最后一块，深度够了再 `setDayRoot` | 改用更早的块凑深度，或把服务器时间当成块时间 |
| 错误 root 且已经扣分 | 订单和 `PointsChanged` 都在 | 关掉 `redeemOpen`，公开 root、块和 orderId，交给 L | 写成「已批准永不退款」并自动结案 |
| `earn` 返回 0 | 验证或找错未记已领 | 用户在条件满足后重试 | 模块把已领写成真来「防重」 |
| 签名人泄露 | 可能滥发 30 或 100，直到预算 | 管理员 `setEarner` 把该 action `enabled=false`，并 `setValidator(addr, false)` | 修改旧 Points 代码 |
| 需要停止新申请 | 旧订单仍在 | `redeemOpen = false` | 暂停或升级 Registrar / Points |

已经成功的兑换，用户不能自己取消或换名。管理员超时只补发，不退款、不重扣、不占新日名额，也不赔 100。这两句是 L 批准的。

错误 root、铸到错误地址、脚本误扣，只有在按 `12` 宣布为事故之后才退 200 并另补 100。没有 `declareAccident` 时不要自动 `refund`，也不要写成永不退款。事故退分不恢复当天 spender 的 gross。

关掉本模块的开关不影响旧的签到、铸造、评价、市场。旧合约没有本季的暂停开关，也不要加。
